# 网站加载与运行优化 · 2026-10-23

本次保持已确认的首页、个人 Logo、第二屏肖像和日夜页脚，重点减少传输、重复下载及持续绘制。改动在 codex/performance-optimization 分支完成，通过 PR 发布至现有 Vercel 项目。

## 主要改动

- 首屏先加载响应式 WebP 封面，关键图片和页面加载完成后在空闲时挂载视频。视频 poster 使用同一张 WebP，不再额外请求 473KB JPG。
- 视频离开首屏或页面进入后台时暂停，回到可见首屏时恢复。用 1% 可见比例排除滚动锚点处的零面积交界，避免第二屏仍持续解码。直接进入联系等区块时，排除锚点滚动尚未完成前短暂经过首屏而触发视频下载的情况。
- 减少动态效果、节省流量、2G / slow-2g 时只使用封面。保留静音、自动播放、循环、playsinline 和移动端媒体切换。
- 重编码保持 12 秒、24fps、288 帧及原分辨率，无音轨；MP4 元数据前置。桌面 WebM 3.04MB → 2.02MB，桌面 MP4 6.80MB → 2.42MB，手机 MP4 3.51MB → 1.42MB。
- 移除鼠标移动跟踪绘制、动态模糊及长期 will-change；入场保留透明度和轻微位移，结束后 transform:none，不长期保留 3D 图层。
- 页脚只挂载当前主题的城市图；切换时使用对应主题底色承接加载，避免旧夜景图与新浅色文字配色错配。
- 152 张项目详情原图合计 181.90MB，新增 1600px / 800px WebP 版本合计分别 18.95MB / 6.16MB，按实际屏幕选择，设置固有尺寸并懒加载。源图仍保留。
- 详情组件和图片清单拆为按需加载模块，不进入首页初始代码。模块网络加载失败时保留导航，并提供重新加载和返回列表入口。
- 个人 Logo 使用 160px 透明无损 WebP，23KB → 1.6KB；原图保留。
- Vercel 对含内容哈希的脚本、样式和新媒体设置一年 immutable 缓存；原有固定地址媒体使用一天缓存。HTML 继续使用平台默认重新验证策略。

## 本轮测量

使用 Lighthouse 13.5、同一 Chrome、默认移动端模拟节流，比较保留的旧生产构建与最终生产构建的本机 loopback preview。每列为一次运行，非真实用户统计。

| 指标 | 优化前移动端 | 最终优化后移动端 |
| --- | ---: | ---: |
| Performance | 98 | 98 |
| LCP | 2.37s | 2.13s |
| 初始传输 | 4.253MB | 1.673MB |
| 请求数 | 17 | 16 |
| TBT | 46ms | 28.5ms |
| CLS | 0 | 0 |

稳定的直接变化是首屏传输减少约 60.7%，以及离屏视频解码和持续绘制的移除。LCP 与 TBT 存在单次测量波动，不据此声称固定提升比例。中间构建曾测得 99 分 / LCP 1.98 秒，未作为最终结果。

桌面构建在最终局部错误恢复和锚点补丁前测得 100 分、LCP 0.69 秒、CLS 0；补丁影响详情页失败提示、页脚图片重新挂载和非首页锚点的首次加载判断，首页媒体文件不变。减少动态效果的功能审计视频请求为零，总传输约 251KB。

优化前线上移动端一次审计为 92 分，初始传输 4.26MB。线上首字节受本机代理与跨境链路影响，不能与 loopback 指标直接比较。本轮未进行真机滚动帧率或真实用户监测，不把 Lighthouse 分数等同于所有设备上的流畅度。

## 验证与证据

- npm run build、npm run lint、git diff --check 通过。
- 1440、1024、768、390px 浏览器布局无横向溢出；手机使用 720p 视频，桌面使用 1080p。
- 实际滚至第二屏后视频 paused=true，返回首屏后 paused=false；视频 duration=12、muted=true、controls=false。
- 项目详情路由加载正常，手机实际选择 800px 图片；返回作品列表正常。
- 单独用缺失详情模块的本地构建模拟网络失败，确认导航、说明、重新加载和返回列表可见。
- 桌面、手机审计都没有重复 JPG 封面或首页提前请求详情模块；减少动态效果的视频请求为零。
- 308 个新媒体文件的内容哈希、尺寸及路径已校验；视频完整解码通过。白天和夜晚视频帧、项目细节图已并排检查。
- 原始报告和截图位于 .tmp/performance/，媒体大小和质量记录位于 .tmp/performance-media/；精简数据见 measurements.json。

媒体处理可复现：使用 Python + Pillow 和 FFmpeg 执行 scripts/optimize-media.py --images --videos --ffmpeg <FFmpeg绝对路径>。该离线脚本不参与网站运行或部署构建，不新增应用依赖。
